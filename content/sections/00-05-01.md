Quando qualcosa va storto Python stampa un **traceback**. Si legge **dal basso**: l'ultima riga dice *che cosa* è successo, le righe sopra *dove*, dalla chiamata più esterna alla più interna.

```text
Traceback (most recent call last):
  File "verifica.py", line 6, in <module>
    print(tensione(12, 0))
  File "verifica.py", line 2, in tensione
    return N * 1000 / A
ZeroDivisionError: division by zero
```

Qui l'ultima riga dice: divisione per zero. Quella sopra indica la riga 2, dentro `tensione`; più su c'è la chiamata che l'ha provocata, con `A = 0`. L'errore non sta nella formula ma nel valore passato.

## Gli errori che incontrerai per primi

| Ultima riga | Che cosa vuol dire | Dove guardare |
|---|---|---|
| `SyntaxError` | Python non riesce nemmeno a leggere il codice | la riga indicata **e quella prima** (una parentesi o i `:` mancanti) |
| `IndentationError` | rientri non coerenti | usa sempre 4 spazi |
| `NameError: name 'sigm' is not defined` | nome scritto male o usato prima di crearlo | maiuscole, refusi, ordine delle righe |
| `TypeError: can only concatenate str` | tipi incompatibili, come `"3" + 2` | converti con `float()` o `str()` |
| `ZeroDivisionError` | divisione per zero | il valore che arriva al denominatore |
| `IndexError: list index out of range` | indice oltre la fine della lista | l'ultimo indice è `len(lista) - 1` |

L'appendice C del Percorso ha la tabella completa, da tenere a portata di mano.

## Gli errori senza traceback

I più insidiosi non fermano il programma: il risultato è semplicemente **sbagliato**. Contro questi l'arma è stampare i valori intermedi. Con `=` dentro le graffe di una f-string Python stampa anche il nome:

```python
F = 12_000      # N
d = 16          # mm
A = 3.1416 * d**2 / 4
sigma = F / A
print(f"{A=:.1f}  {sigma=:.1f}")
```

Se un valore non ti torna, sai a quale riga fermarti. Un buon controllo è sempre un **caso di cui conosci il risultato**: un quadrato di lato 1, una trave di cui hai il risultato del libro, una forza nulla.

```python
def area_rett(b, h):
    return b * h

print(area_rett(1, 1))     # deve dare 1
print(area_rett(2, 3))     # deve dare 6
```

## Un metodo, non la fortuna

1. Leggi l'ultima riga del traceback e cerca la riga del **tuo** file più in basso.
2. Riproduci l'errore con il caso più piccolo possibile.
3. Stampa i valori appena prima della riga che sbaglia.
4. Cambia **una cosa alla volta** e riprova.

> [!desktop] Al computer, scrivi `breakpoint()` nella riga che ti interessa: il programma si ferma lì e puoi ispezionare le variabili. Comandi utili: `p nome` stampa un valore, `n` passa alla riga dopo, `c` continua, `q` esce. In VS Code fai lo stesso cliccando a sinistra del numero di riga e premendo F5.

> [!trappola] Non fermarti alla prima riga del traceback: parla del punto di partenza, non dell'errore. La riga che conta è **l'ultima**.

> [!ing] Nei calcoli tecnici gli errori più frequenti sono di **unità** (mm e m, kN e N): metti le unità nei commenti e stampa i valori intermedi con l'unità accanto. Un risultato mille volte troppo grande è quasi sempre una conversione dimenticata.
