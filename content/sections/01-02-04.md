Ogni funzione ha il suo spazio di nomi. Un nome **assegnato** dentro la funzione è **locale**: nasce alla chiamata e sparisce alla fine. Un nome solo **letto** viene cercato fuori, nel modulo.

```python
G = 9.81                 # m/s², letta dalla funzione

def peso(m):
    P = m * G            # P è locale
    return P

print(peso(80))
P = 5
print(peso(10), P)       # la P di fuori non è stata toccata
```

Python cerca un nome in quest'ordine: **L**ocale, funzioni **E**sterne che la contengono, **G**lobale (il modulo), **B**uilt-in (`print`, `len`…). È la regola *LEGB*.

## L'errore classico: UnboundLocalError

Basta **un** assegnamento in qualsiasi punto della funzione perché quel nome sia locale in **tutta** la funzione, anche nelle righe prima:

```python norun
contatore = 0

def conta():
    contatore += 1       # assegna → contatore è locale, ma non ha ancora un valore

conta()
```

```text
UnboundLocalError: cannot access local variable 'contatore' where it is not associated with a value
```

Con `global contatore` in cima alla funzione funzionerebbe, ma è quasi sempre la scelta sbagliata: la funzione cambia qualcosa di nascosto e chiamarla due volte dà risultati diversi. Meglio **ricevere** i dati come parametri e **restituire** il risultato.

```python
def conta_sopra(valori, soglia):
    n = 0                    # contatore locale: riparte da zero a ogni chiamata
    for v in valori:
        if v > soglia:
            n += 1
    return n

print(conta_sopra([0.8, 1.2, 1.05], 1.0))
print(conta_sopra([0.8, 1.2, 1.05], 1.0))   # stesso risultato
```

## Parametri modificabili

Una lista passata a una funzione **non** viene copiata: il parametro è un altro nome per lo stesso oggetto (come hai visto in «Nomi, oggetti e identità»). Se la funzione la modifica, la modifica si vede anche fuori.

```python
def aggiungi_peso_proprio(carichi, p):
    carichi.append(p)        # modifica la lista di chi chiama

def con_peso_proprio(carichi, p):
    return carichi + [p]     # nuova lista, l'originale resta com'è

c = [10, 20]
nuovi = con_peso_proprio(c, 2)
print(c, nuovi)
aggiungi_peso_proprio(c, 2)
print(c)
```

Decidi sempre quale delle due vuoi e scrivilo nella docstring.

## Niente ambito di blocco

A differenza del C e di Java, `if` e `for` **non** creano un nuovo ambito: una variabile creata dentro un ciclo esiste anche dopo.

```python
for i in range(3):
    ultimo = i * 10
print(i, ultimo)
```

> [!c] In C una variabile dichiarata dentro `{ }` sparisce alla fine del blocco. In Python l'unità di ambito è la **funzione** (e il modulo), non il blocco.

> [!trappola] Le costanti di modulo vanno benissimo (per convenzione in MAIUSCOLO: `G`, `E_ACCIAIO`). Il problema nasce quando una funzione le **modifica**: lì serve un parametro e un `return`.

> [!ing] Funzioni che dipendono solo dai parametri (*funzioni pure*) si verificano una per una con un caso noto e si riusano ovunque. È così che si costruisce un formulario affidabile, come nel Progetto 1.
