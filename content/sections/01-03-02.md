Quando qualcosa va storto Python solleva un'**eccezione**. Con `try`/`except` la intercetti e decidi cosa fare, invece di far fermare tutto il programma.

```python
letture = ["21.5", "21,8", "n.d.", "22.1"]
valide = []
for x in letture:
    try:
        valide.append(float(x.replace(",", ".")))
    except ValueError:
        print("Lettura scartata:", x)
print(valide)
```

## Che cosa succede quando c'è un errore

Senza `try`, un'eccezione **ferma il programma**: le righe successive non vengono eseguite. Con `try`/`except` dici a Python: «prova a fare questo; se succede *quel* problema, fai quest'altro e vai avanti».

```python
def converti(testo):
    try:
        return float(testo)          # 1. prova
    except ValueError:               # 2. se float() non riesce…
        return None                  # 3. …restituisci None invece di fermarti

print(converti("21.5"))     # → 21.5
print(converti("n.d."))     # → None
print("il programma continua")
```

Passo per passo: Python esegue il blocco `try`. Se va tutto bene, l'`except` viene saltato. Se una riga solleva l'eccezione indicata (`ValueError`), il resto del blocco `try` viene abbandonato e si esegue il blocco `except`. Un'eccezione di **tipo diverso** non viene intercettata e ferma comunque il programma.

## Intercettare solo quello che ti aspetti

Elenca le eccezioni che sai gestire; un `except:` senza tipo nasconderebbe anche gli errori veri (un nome scritto male, un indice sbagliato) e renderebbe il debug un incubo.

```python
def tensione_letta(F_testo, A):
    try:
        return float(F_testo) / A
    except ValueError:
        print("forza non leggibile:", F_testo)
    except ZeroDivisionError:
        print("area nulla")
    return None

tensione_letta("12000", 200)       # va bene: nessun messaggio
tensione_letta("dodicimila", 200)  # → forza non leggibile: dodicimila
tensione_letta("12000", 0)         # → area nulla
```

Con `except ValueError as e:` hai anche il messaggio dell'errore in `e`, utile da stampare.

## Le eccezioni più comuni

| Eccezione | Quando succede |
| --- | --- |
| `ValueError` | valore del tipo giusto ma sbagliato, es. `float("abc")` |
| `TypeError` | tipo sbagliato, es. `"3" + 4` |
| `ZeroDivisionError` | divisione per zero |
| `KeyError` / `IndexError` | chiave o indice inesistente |
| `FileNotFoundError` | file che non c'è |

## Sollevare le tue eccezioni

Quando un input non ha senso fisico, **fermati subito** con un messaggio chiaro:

```python
def tensione(F, A):
    if A <= 0:
        raise ValueError(f"Area non valida: {A} mm²")
    return F / A

try:
    tensione(1000, 0)
except ValueError as e:
    print("Errore:", e)
```

## else e finally

```python
try:
    risultato = 10 / 2
except ZeroDivisionError:
    print("divisione per zero")
else:
    print("tutto ok:", risultato)    # solo se non ci sono stati errori
finally:
    print("eseguito sempre")
```

## raise: quando fermarsi è la cosa giusta

Non tutti gli errori vanno «aggiustati». Una funzione di calcolo che riceve un dato senza senso fisico deve **fermarsi e dirlo**, non restituire un numero sbagliato. Chi la chiama deciderà cosa fare.

```python
def snellezza(L, i):
    if L <= 0 or i <= 0:
        raise ValueError(f"lunghezza e raggio d'inerzia devono essere positivi (L={L}, i={i})")
    return L / i

print(snellezza(3000, 30))    # → 100.0
try:
    snellezza(3000, -30)
except ValueError as e:
    print("Dato rifiutato:", e)
```

Regola pratica: `raise` dentro le funzioni di calcolo, `try`/`except` dove si leggono i dati (file, input) e si decide come reagire.

> [!trappola] `except:` da solo cattura tutto, anche gli errori di battitura nel codice: nasconde i bug. Specifica sempre il tipo di eccezione.

> [!ing] "Fallisci presto e chiaramente": una funzione di verifica che accetta un diametro negativo e restituisce un numero è più pericolosa di una che si ferma con un errore.

## Riepilogo

- Un'eccezione non gestita ferma il programma; `try`/`except Tipo:` la intercetta e prosegue.
- Intercetta solo le eccezioni che sai gestire; mai `except:` senza tipo.
- `except Tipo as e` dà il messaggio; `else` se non ci sono errori; `finally` sempre.
- `raise ValueError("…")` ferma una funzione che riceve dati senza senso.
