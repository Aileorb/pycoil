Quando una classe serve soprattutto a **contenere dati**, il decoratore `@dataclass` scrive per te `__init__`, `__repr__` e `__eq__`. Basta elencare i campi con il loro tipo.

```python
from dataclasses import dataclass

@dataclass
class Materiale:
    nome: str
    fy: float        # MPa
    E: float = 210_000.0
    rho: float = 7850.0   # kg/m³

s355 = Materiale("S355", 355)
print(s355)
print(s355 == Materiale("S355", 355))
```

## Metodi e campi calcolati

Una dataclass resta una classe: puoi aggiungere metodi.

```python
from dataclasses import dataclass, field

@dataclass
class Materiale:
    nome: str
    fy: float
    E: float = 210_000.0

    def deformazione_snervamento(self):
        return self.fy / self.E

@dataclass
class Trave:
    materiale: Materiale
    L: float               # mm
    carichi: list[float] = field(default_factory=list)   # kN

t = Trave(Materiale("S275", 275), 4000)
t.carichi.append(12.5)
print(t, f"{t.materiale.deformazione_snervamento():.5f}")
```

`field(default_factory=list)` crea una lista nuova per ogni trave: è il modo corretto di avere un default mutabile.

## Dati che non devono cambiare

Con `frozen=True` l'oggetto diventa immutabile: ideale per una tabella di materiali di riferimento.

```python
from dataclasses import dataclass

@dataclass(frozen=True)
class Acciaio:
    nome: str
    fy: float

S235 = Acciaio("S235", 235)
try:
    S235.fy = 300
except Exception as e:
    print(type(e).__name__, "-> un materiale di riferimento non si modifica")
```

> [!ing] Nel Progetto 2 costruirai una piccola libreria con `Materiale`, `Sezione` e `Trave` proprio così: dati chiari, verifiche come metodi, test automatici.

> [!trappola] Le annotazioni (`fy: float`) non controllano niente a runtime: `Materiale("S355", "tanto")` funziona. I tipi servono a te e agli strumenti come mypy (Parte II, type hint).
