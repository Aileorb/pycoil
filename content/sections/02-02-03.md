Per ordinare oggetti hai due strade: dire a `sorted` **quale chiave** usare con `key=`, oppure rendere gli oggetti **confrontabili** con `order=True` nelle dataclass.

```python
from dataclasses import dataclass

@dataclass
class Componente:
    nome: str
    sigma: float      # MPa

pezzi = [Componente("albero", 180), Componente("perno", 240), Componente("staffa", 95)]
for c in sorted(pezzi, key=lambda c: c.sigma, reverse=True):
    print(f"{c.nome:<8}{c.sigma:>6.0f} MPa")
```

## order=True

Con `order=True` la dataclass genera `<`, `<=`, `>`, `>=` confrontando i campi **nell'ordine in cui li scrivi**, come tuple:

```python
from dataclasses import dataclass, field

@dataclass(order=True)
class Verifica:
    utilizzo: float
    elemento: str = field(compare=False)   # escluso dai confronti

v = [Verifica(0.82, "trave A"), Verifica(1.07, "colonna 3"), Verifica(0.45, "controvento")]
print(max(v))
print([x.elemento for x in sorted(v)])
```

## Chiavi multiple

`key` può restituire una tupla: ordina per il primo elemento, a parità per il secondo.

```python
viti = [("M8", 8.8), ("M10", 10.9), ("M8", 10.9), ("M10", 8.8)]
print(sorted(viti, key=lambda v: (int(v[0][1:]), -v[1])))
```

## operator.attrgetter

Per chiavi semplici `operator.attrgetter` e `itemgetter` sono più leggibili delle lambda:

```python
from operator import attrgetter, itemgetter
from dataclasses import dataclass

@dataclass
class Profilo:
    nome: str
    peso: float
    Wy: float

cat = [Profilo("IPE200", 22.4, 194e3), Profilo("HEA160", 30.4, 220e3), Profilo("IPE220", 26.2, 252e3)]
leggeri_ok = sorted((p for p in cat if p.Wy >= 200e3), key=attrgetter("peso"))
print(leggeri_ok[0].nome)
print(sorted([(3, "c"), (1, "a")], key=itemgetter(0)))
```

> [!trappola] `sorted()` restituisce una lista nuova; `lista.sort()` ordina sul posto e restituisce `None`: `x = lista.sort()` lascia `x` vuoto.

> [!ing] "Il profilo più leggero che verifica" è il problema di ogni dimensionamento: filtro + `min(..., key=peso)`.
