Una classe **figlia** eredita attributi e metodi dalla classe **madre**, scritta tra parentesi. Può aggiungerne di nuovi o **ridefinire** quelli che cambiano. Così il codice comune sta in un posto solo.

```python
class Sezione:
    def modulo_resistenza(self):
        return self.inerzia() / self.y_max()    # uguale per tutte le sezioni

class Rettangolo(Sezione):
    def __init__(self, b, h):
        self.b, self.h = b, h
    def inerzia(self):
        return self.b * self.h**3 / 12
    def y_max(self):
        return self.h / 2

r = Rettangolo(30, 50)                # mm
print(r.modulo_resistenza())          # metodo ereditato da Sezione
```

## Polimorfismo: un ciclo per tutte le sezioni

Ogni figlia ridefinisce i suoi metodi; chi le usa chiama sempre gli stessi nomi, senza sapere di che forma si tratta.

```python
import math

class Sezione:
    def modulo_resistenza(self):
        return self.inerzia() / self.y_max()

class Rettangolo(Sezione):
    def __init__(self, b, h):
        self.b, self.h = b, h
    def inerzia(self):
        return self.b * self.h**3 / 12
    def y_max(self):
        return self.h / 2

class Cerchio(Sezione):
    def __init__(self, d):
        self.d = d
    def inerzia(self):
        return math.pi * self.d**4 / 64
    def y_max(self):
        return self.d / 2

M = 2.0e6     # N·mm
for s in [Rettangolo(30, 50), Cerchio(40)]:
    print(f"{type(s).__name__:10} σ = {M / s.modulo_resistenza():6.1f} MPa")
```

## super(): estendere invece di riscrivere

Quando la figlia ha bisogno di **più** dati, il suo `__init__` chiama quello della madre con `super().__init__(...)`. Lo stesso vale per qualsiasi metodo: `super().area()` usa la versione della madre e ci aggiunge qualcosa.

```python
import math

class Cerchio:
    def __init__(self, d):
        self.d = d
    def area(self):
        return math.pi * self.d**2 / 4

class Tubo(Cerchio):
    def __init__(self, D, s):
        super().__init__(D)          # imposta self.d = D
        self.s = s                   # spessore
    def area(self):
        interno = Cerchio(self.d - 2 * self.s)
        return super().area() - interno.area()

t = Tubo(60.3, 3.2)
print(f"A = {t.area():.1f} mm²")
print(isinstance(t, Cerchio), isinstance(t, Tubo))
```

`isinstance(t, Cerchio)` è vero: un tubo **è un** cerchio con qualcosa in più, quindi va bene ovunque serva un `Cerchio`.

## Un metodo che le figlie devono scrivere

Se la madre non sa calcolare qualcosa, lo dice in modo esplicito con `NotImplementedError`: chi dimentica di ridefinire il metodo se ne accorge subito.

```python
class Carico:
    def risultante(self):
        raise NotImplementedError("ogni carico calcola la sua risultante")

class Distribuito(Carico):
    def __init__(self, q, L):
        self.q, self.L = q, L        # kN/m, m
    def risultante(self):
        return self.q * self.L

print(Distribuito(4.0, 6.0).risultante(), "kN")
```

## Ereditare o contenere?

La domanda da farsi: è un **«è un»** o un **«ha un»**? Un tubo *è una* sezione: ereditarietà. Una trave *ha una* sezione: la trave tiene un attributo `self.sezione`, non eredita da `Sezione`. Nel dubbio, la seconda strada (*composizione*) è più flessibile.

> [!java] Come in Java, ma senza `extends`: la madre va tra parentesi. Python ammette anche l'ereditarietà multipla (`class C(A, B)`), però nel codice tecnico si usa poco: preferisci gerarchie corte, di uno o due livelli.

> [!trappola] Se la figlia scrive il suo `__init__` e **dimentica** `super().__init__(...)`, gli attributi della madre non vengono creati e più avanti arriva un `AttributeError`.

> [!ing] Le librerie che userai sono costruite così: in Matplotlib tutti gli oggetti disegnabili derivano da `Artist`, in scikit-fem tutti gli elementi da `Element`. Saper leggere una gerarchia di classi ti fa capire la documentazione.
