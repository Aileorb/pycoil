Un **generatore** è una funzione che usa `yield` invece di `return`: produce i valori **uno alla volta**, solo quando servono. Non tiene tutto in memoria, quindi va bene anche per file enormi o sequenze infinite.

```python
def passi_di_carico(F_max, n):
    """Rampa di carico da 0 a F_max in n passi."""
    for i in range(1, n + 1):
        yield F_max * i / n

for F in passi_di_carico(1000, 4):
    print(F)
```

## Il problema che risolvono

Una lista tiene **tutti** i valori in memoria nello stesso momento. Con un milione di letture di un sensore va ancora bene; con un file da dieci gigabyte no. Un **generatore** produce i valori **uno alla volta, quando servono**: ne tiene in memoria uno solo.

## yield, passo per passo

Una funzione con `yield` invece di `return` non restituisce un valore: restituisce un **generatore**. Il corpo parte solo quando chiedi il primo valore, si ferma al `yield` consegnandolo, e alla richiesta successiva **riprende da lì**.

```python
def rampa(da, a, passo):
    print("inizio")
    x = da
    while x <= a:
        yield x            # consegna x e si mette in pausa
        x += passo
    print("fine")

g = rampa(0, 10, 5)
print(type(g).__name__)    # → generator   (nessun «inizio» ancora!)
for carico in g:
    print("carico", carico)
```

Eseguendo vedi `inizio`, poi `carico 0`, `carico 5`, `carico 10`, poi `fine`: il corpo della funzione avanza a pezzi, intercalato con il ciclo.

## Si consumano una volta sola

Un generatore, una volta arrivato in fondo, è esaurito. Per ripartire se ne crea uno nuovo:

```python
g = (x * x for x in range(4))
print(sum(g))      # → 14
print(sum(g))      # → 0   (è già stato consumato)
```

## Come funziona

`for` chiama `iter()` sull'oggetto e poi `next()` finché non arriva `StopIteration`. Un generatore fa tutto da solo e si ferma nel punto del `yield`, riprendendo da lì alla chiamata successiva.

```python
g = passi = (x * x for x in range(3))   # espressione generatrice
print(next(g), next(g), next(g))
try:
    next(g)
except StopIteration:
    print("finito")
```

## Pipeline di dati

I generatori si concatenano: ogni stadio prende il precedente. Niente liste intermedie.

```python
testo = """# prova 7
0;0
0,5;120

1;ERR
1,5;365"""

def righe_utili(righe):
    for r in righe:
        r = r.strip()
        if r and not r.startswith("#"):
            yield r

def coppie(righe):
    for r in righe:
        t, F = r.replace(",", ".").split(";")
        try:
            yield float(t), float(F)
        except ValueError:
            continue

dati = coppie(righe_utili(testo.splitlines()))
print(max(dati, key=lambda c: c[1]))
```

Con un file vero basterebbe passare `open("prova.csv")`: il file viene letto una riga alla volta.

## itertools

```python
from itertools import accumulate, pairwise, islice, count

spostamenti = [0.0, 0.4, 0.9, 1.1]
print(list(pairwise(spostamenti)))                        # tratti consecutivi
print([round(b - a, 2) for a, b in pairwise(spostamenti)])
print(list(accumulate([3, 5, 2])))                        # somme cumulate
print(list(islice(count(0, 0.25), 5)))                    # i primi 5 di una sequenza infinita
```

> [!trappola] Un generatore si consuma una volta sola: dopo averlo scorso, un secondo `for` non produce nulla. Se ti servono i dati due volte, salvali in una lista.

> [!ing] I log delle macchine di prova arrivano a milioni di righe: leggerli con un generatore evita di riempire la memoria.

## Riepilogo

- Una funzione con `yield` restituisce un generatore: produce i valori uno alla volta.
- Il corpo si ferma a ogni `yield` e riprende alla richiesta successiva (`for` o `next`).
- I generatori non tengono tutto in memoria e si consumano una volta sola.
- `(espr for x in seq)` è un generatore in una riga; `itertools` ne offre di pronti.
