## Perché questi strumenti

Quando i programmi crescono servono tre cose che l'app fa per te ma che al computer devi organizzare: **un ambiente** con le librerie giuste per ogni progetto, **un modo di provare** che i calcoli siano ancora corretti dopo ogni modifica, e **una storia** delle versioni per tornare indietro. Sono ambiente virtuale, pytest e Git.

## Un test, passo per passo

Un test è una funzione che si chiama `test_qualcosa` e contiene degli `assert`: «verifica che questa condizione sia vera». Se lo è, non succede niente; se non lo è, solleva `AssertionError` e il test fallisce.

```python
def area_cerchio(d):
    return 3.1416 * d**2 / 4

def test_area_cerchio():
    assert area_cerchio(0) == 0                  # caso banale
    assert abs(area_cerchio(2) - 3.1416) < 1e-9  # caso noto: d = 2 → π

test_area_cerchio()
print("test superato")             # → test superato
```

Al computer non chiami i test a mano: scrivi le funzioni `test_*` in un file `test_qualcosa.py` e lanci `pytest` nel terminale. Lui le trova, le esegue tutte e ti dice quali falliscono e perché. Le task avanzate di PyCoil funzionano così.

Che cosa testare: un caso banale (zero, uno), un caso di cui conosci il risultato dal libro, e un caso limite (valori negativi, liste vuote).

## Ambiente virtuale

Ogni progetto ha la sua cartella `.venv` con le versioni delle librerie che usa. `requirements.txt` permette a chiunque (anche a te tra un anno) di ricreare lo stesso ambiente con `pip install -r requirements.txt`.

Struttura consigliata:

```text
trave/
├── .venv/              (non va su Git)
├── trave.py            il tuo modulo
├── test_trave.py       i test
├── esplorazione.ipynb  il notebook
└── requirements.txt
```

## pytest

Un test è una funzione che inizia con `test_` e contiene `assert`. pytest li trova da solo.

```python
# test_trave.py — puoi provarlo anche qui: le funzioni sono normali funzioni Python
import math
from pytest import approx

def freccia_mezzeria(q, L, EI):
    return 5 * q * L**4 / (384 * EI)

def test_freccia_nota():
    assert freccia_mezzeria(1, 1, 5 / 384) == approx(1)

def test_proporzionale_al_carico():
    assert freccia_mezzeria(2, 3, 1) == approx(2 * freccia_mezzeria(1, 3, 1))

test_freccia_nota(); test_proporzionale_al_carico()
print("test superati")
```

Sul computer:

```bash
pytest -q          # tutti i test
pytest -q -k freccia   # solo quelli che contengono "freccia"
```

`approx` confronta i float con una tolleranza: mai `==` tra numeri calcolati.

## Jupyter

```bash
jupyter lab
```

Un notebook alterna celle di codice e di testo (Markdown con formule `$\sigma = N/A$`). Ottimo per esercitazioni e relazioni; quando una funzione diventa stabile, spostala in un modulo `.py` e importala nel notebook.

## Git in due minuti

```bash
git init
echo ".venv/" > .gitignore
git add .
git commit -m "Prima versione del calcolo della trave"
```

> [!desktop] Questa sezione si fa al computer: i comandi vanno nel terminale. I progetti di PyCoil usano esattamente questo flusso.

> [!trappola] Se `pip install` "funziona" ma poi `import numpy` fallisce, quasi sempre l'ambiente virtuale non è attivo, o l'editor usa un altro interprete: in VS Code scegli l'interprete `.venv` in basso a destra.

## Riepilogo

- Un ambiente virtuale (`python -m venv .venv`) tiene le librerie di ogni progetto separate.
- Un test è una funzione `test_*` con `assert`; `pytest` li trova e li esegue tutti.
- Con i float si confronta con `pytest.approx`, mai con `==`.
- Jupyter per esplorare e fare grafici; Git per tenere la storia del codice.
