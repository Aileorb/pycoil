**pint** associa a ogni numero la sua **unità di misura**. Le conversioni diventano automatiche e, soprattutto, sommare grandezze incompatibili dà subito un errore invece di un risultato sbagliato.

```python
import pint
u = pint.UnitRegistry()

F = 12 * u.kN
d = 16 * u.mm
sigma = (4 * F / (3.1416 * d**2)).to(u.MPa)
print(sigma)
print(f"{sigma:.1f~P}")        # formato compatto con simboli
```

Nell'app la libreria si scarica da PyPI al primo uso: la prima esecuzione richiede qualche secondo in più.

<!-- /card -->

## Il problema che risolve

Quasi tutti gli errori gravi nei calcoli tecnici sono di **unità**: millimetri usati come metri, kN come N, bar come Pa. Python vede solo numeri e non se ne accorge. Con `pint` ogni numero porta con sé la sua unità: le conversioni diventano automatiche e un'operazione senza senso (sommare metri e secondi) si ferma con un errore.

## Passo per passo

```python
import pint
u = pint.UnitRegistry()               # il «dizionario» delle unità: uno per programma
F = 12 * u.kN                         # numero × unità = grandezza
A = 80 * u.mm**2
sigma = F / A
print(sigma)                          # → 0.15 kilonewton / millimeter ** 2
print(sigma.to(u.MPa))                # → 150.0 megapascal
print(round(sigma.to(u.MPa).magnitude))   # → 150
```

1. `UnitRegistry()` crea il registro con tutte le unità; si crea **una volta** e si usa ovunque.
2. `12 * u.kN` crea una *Quantity*: valore e unità insieme.
3. Le operazioni combinano anche le unità: kN / mm².
4. `.to(unità)` converte; `.magnitude` restituisce il solo numero (quando devi passarlo a una funzione che non conosce pint).

## Conversioni

```python
import pint
u = pint.UnitRegistry()
p = 3.5 * u.bar
print(p.to(u.kPa), p.to(u.psi).round(2))
P = 75 * u.kW
n = 1450 / u.minute
C = (P / (2 * 3.14159 * n)).to(u.N * u.m)     # coppia = potenza / velocità angolare
print(f"coppia = {C:.1f}")
print(u.Quantity(20, u.degC).to(u.K))       # le temperature con offset si creano con Quantity
```

## Gli errori che pint ferma

```python
import pint
u = pint.UnitRegistry()
try:
    print(10 * u.mm + 3 * u.N)
except pint.DimensionalityError as e:
    print("Errore:", e)
L = 2 * u.m + 350 * u.mm                      # unità diverse ma compatibili: va bene
print(L, "=", L.to(u.m))
```

## Funzioni con le unità controllate

`u.wraps` dichiara le unità di ingresso e di uscita: chi chiama può usare qualsiasi unità compatibile.

```python
import pint
u = pint.UnitRegistry()

@u.wraps(u.mm, (u.N, u.mm, u.MPa, u.mm**4))
def freccia_mensola(F, L, E, I):
    return F * L**3 / (3 * E * I)

print(freccia_mensola(1 * u.kN, 1.2 * u.m, 210 * u.GPa, 8.5e5 * u.mm**4))
```

## Con NumPy

```python
import numpy as np
import pint
u = pint.UnitRegistry()
v = np.array([10, 20, 30]) * u.km / u.hour
print(v.to(u.m / u.s))
energia = (0.5 * 1200 * u.kg * v**2).to(u.kJ)
print(energia)
```

> [!trappola] Crea **un solo** `UnitRegistry` per programma: grandezze di registri diversi non si possono combinare tra loro.

> [!ing] La sonda Mars Climate Orbiter andò persa nel 1999 per un errore tra libbre-forza e newton. Nei calcoli che passano tra più persone le unità esplicite sono un'assicurazione.

## Riepilogo

- `u = pint.UnitRegistry()` una volta; `valore * u.unità` crea una grandezza con unità.
- Le operazioni combinano le unità; `.to(u.MPa)` converte, `.magnitude` dà il numero.
- Somme di unità incompatibili si fermano con `DimensionalityError`.
- `@u.wraps` o i controlli di dimensione per funzioni a prova di unità; funziona anche con NumPy.
