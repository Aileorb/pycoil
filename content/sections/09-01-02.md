I banchi prova, i PLC e i solutori scrivono file di testo pensati per le persone, non per i programmi: numeri in mezzo alle parole, unità attaccate ai valori, righe di formati diversi. Le **espressioni regolari** (*regex*) descrivono la forma del testo che cerchi e lo estraggono.

```python
import re

riga = "2026-03-14 10:22:05 PROVA 17 F=12.5kN T=23.4°C esito=OK"
print(re.findall(r"\d+\.\d+", riga))          # → ['12.5', '23.4']
m = re.search(r"F=(\d+\.\d+)kN", riga)
print(float(m.group(1)) * 1000, "N")          # → 12500.0 N
```

`\d+` vuol dire «una o più cifre», `\.` un punto vero; le parentesi tonde **catturano** la parte che ti interessa, che poi leggi con `group(1)`.

## Perché le stringhe con la r davanti

Le regex usano molto la barra rovesciata `\`, che nelle stringhe normali di Python ha già un significato (`\n` è «a capo»). La `r` davanti alla stringa (*raw string*) dice a Python di lasciare le barre come sono: scrivi **sempre** le regex come `r"..."`.

```python
print(len("\n"), len(r"\n"))     # → 1 2
```

## I mattoni

| Simbolo | Significato | Esempio | Corrisponde a |
|---|---|---|---|
| `\d` | una cifra | `\d\d` | `07` |
| `\w` | lettera, cifra o `_` | `\w+` | `S355` |
| `\s` | spazio, tab, a capo | `F\s*=` | `F=` e `F  =` |
| `.` | qualunque carattere (tranne a capo) | `M.2` | `M12`, `MX2` |
| `[...]` | uno dei caratteri elencati | `[+-]` | `+` o `-` |
| `[^...]` | un carattere **non** elencato | `[^;]+` | testo fino al `;` |
| `*` | zero o più volte | `\d*` | anche niente |
| `+` | una o più volte | `\d+` | `1`, `12`, `125` |
| `?` | zero o una volta (facoltativo) | `-?\d+` | `5` e `-5` |
| `{n,m}` | da n a m volte | `\d{4}` | `2026` |
| `^` `$` | inizio e fine del testo (o della riga) | `^ERR` | righe che iniziano con ERR |
| `\|` | alternativa | `OK\|KO` | `OK` o `KO` |
| `( )` | gruppo che cattura | `(\d+)mm` | cattura `12` da `12mm` |
| `\` | rende normale un carattere speciale | `\.` `\(` | un punto, una parentesi |

## Costruire una regex un pezzo alla volta

Obiettivo: riconoscere una filettatura metrica come `M12x1.75` e leggere diametro e passo. Si parte dal pezzo più semplice e si aggiunge un mattone alla volta, provando a ogni passo.

```python
import re

testo = "Viti M12x1.75 e M8x1.25, dado M10"
print(re.findall(r"M\d+", testo))                      # → ['M12', 'M8', 'M10']
print(re.findall(r"M\d+x\d+\.\d+", testo))             # → ['M12x1.75', 'M8x1.25']
print(re.findall(r"M(\d+)x(\d+\.\d+)", testo))         # → [('12', '1.75'), ('8', '1.25')]
print(re.findall(r"M(\d+)(?:x(\d+\.\d+))?", testo))    # → [('12', '1.75'), ('8', '1.25'), ('10', '')]
```

1. `M\d+`: la lettera M seguita da cifre: trova anche `M10`, che non ha il passo.
2. Aggiungendo `x\d+\.\d+` restano solo le filettature con il passo scritto.
3. Le parentesi catturano i due numeri: `findall` restituisce allora una **tupla** per ogni corrispondenza.
4. `(?:...)?` è un gruppo che **non** cattura, reso facoltativo da `?`: il passo può mancare (filettatura a passo grosso), e in quel caso il secondo gruppo è vuoto.

> [!nota] Per provare una regex prima di scriverla nel codice c'è regex101.com: incolli il testo, scrivi lo schema e vedi subito cosa corrisponde e perché. Ricordati di scegliere il linguaggio **Python**.

## search, match, fullmatch, findall, finditer

| Funzione | Cosa fa | Restituisce |
|---|---|---|
| `re.search(p, s)` | cerca la **prima** corrispondenza ovunque | un oggetto `Match` o `None` |
| `re.match(p, s)` | come `search`, ma solo all'**inizio** del testo | `Match` o `None` |
| `re.fullmatch(p, s)` | il testo **intero** deve corrispondere | `Match` o `None` |
| `re.findall(p, s)` | **tutte** le corrispondenze | lista di stringhe (o di tuple, se ci sono gruppi) |
| `re.finditer(p, s)` | tutte, una alla volta | oggetti `Match` |

`fullmatch` è quella giusta per **validare** un codice: deve avere quella forma e nient'altro.

```python
import re

def codice_valido(c):
    """Codice articolo: due lettere maiuscole, un trattino, quattro cifre (es. AB-1234)."""
    return re.fullmatch(r"[A-Z]{2}-\d{4}", c) is not None

for c in ["AB-1234", "ab-1234", "AB-12345", "XAB-1234"]:
    print(c, codice_valido(c))
```

Uscita:

```text
AB-1234 True
ab-1234 False
AB-12345 False
XAB-1234 False
```

Con `search` al posto di `fullmatch`, `AB-12345` e `XAB-1234` sarebbero passati: contengono un pezzo valido.

Un `Match` va **sempre** controllato prima dell'uso: se la regex non trova niente il risultato è `None`, e `None.group(1)` dà errore.

```python
import re

m = re.search(r"T=(-?\d+\.?\d*)", "P=2.1bar")
if m is None:
    print("temperatura assente")      # → temperatura assente
else:
    print(float(m.group(1)))
```

## Gruppi con nome

Con tanti gruppi, `group(3)` diventa illeggibile. `(?P<nome>...)` dà un nome a ogni gruppo, e `groupdict()` restituisce direttamente un dizionario.

```python
import re

RIGA = re.compile(
    r"(?P<data>\d{4}-\d{2}-\d{2}) (?P<ora>\d{2}:\d{2}:\d{2}) "
    r"PROVA (?P<n>\d+) F=(?P<F>[\d.]+)kN T=(?P<T>-?[\d.]+)°C esito=(?P<esito>OK|KO)"
)
m = RIGA.search("2026-03-14 10:22:05 PROVA 17 F=12.5kN T=23.4°C esito=OK")
d = m.groupdict()
print(d["n"], d["F"], d["esito"])                  # → 17 12.5 OK
misura = {"n": int(d["n"]), "F": float(d["F"]) * 1e3, "ok": d["esito"] == "OK"}
print(misura)                                       # → {'n': 17, 'F': 12500.0, 'ok': True}
```

- `re.compile` prepara la regex una volta sola: utile quando la usi su migliaia di righe, e permette di darle un nome;
- due stringhe `r"..."` una sotto l'altra, dentro le parentesi, vengono unite: così una regex lunga resta leggibile;
- i gruppi restituiscono **sempre testo**: la conversione in numeri la fai tu, come per i CSV.

## Avide e pigre

`*` e `+` sono **avidi**: prendono più testo possibile. Aggiungendo `?` (`*?`, `+?`) diventano **pigri** e si fermano alla prima occasione.

```python
import re

s = "[S355] lotto 4 [ok] verificato"
print(re.findall(r"\[.*\]", s))      # → ['[S355] lotto 4 [ok]']
print(re.findall(r"\[.*?\]", s))     # → ['[S355]', '[ok]']
print(re.findall(r"\[([^\]]*)\]", s))   # → ['S355', 'ok']
```

La terza forma, «tutto tranne la parentesi di chiusura», è spesso la più chiara: dice esattamente cosa può stare dentro.

## Sostituire con re.sub

`re.sub(schema, sostituto, testo)` sostituisce ogni corrispondenza. Nel sostituto, `\1`, `\2` richiamano i gruppi catturati. L'uso più frequente in Italia: la virgola decimale.

```python
import re

riga = "12,5;0,003;210,0"
print(re.sub(r"(\d),(\d)", r"\1.\2", riga))      # → 12.5;0.003;210.0
print(re.sub(r"\s+", " ", "F  =   12.5    kN"))  # → F = 12.5 kN
```

Il sostituto può anche essere una **funzione**, che riceve il `Match` e restituisce il testo: utile per convertire unità dentro un testo.

```python
import re

def in_mm(m):
    return f"{float(m.group(1)) * 25.4:.1f} mm"

print(re.sub(r"(\d+(?:\.\d+)?)\s*in\b", in_mm, "foro 0.5 in, interasse 2 in"))   # → foro 12.7 mm, interasse 50.8 mm
```

`\b` è il **confine di parola**: evita che `in` corrisponda dentro `interasse`.

## Flag: maiuscole e righe

- `re.IGNORECASE` (o `re.I`): non distingue maiuscole e minuscole;
- `re.MULTILINE` (o `re.M`): `^` e `$` valgono all'inizio e alla fine di **ogni riga**, non solo del testo intero.

```python
import re

log = """INFO avvio banco
WARN temperatura olio 71 °C
info carico applicato
ERROR cella di carico non risponde
WARN temperatura olio 74 °C"""

print(len(re.findall(r"^info", log, re.I | re.M)))       # → 2
print(re.findall(r"^WARN .*?(\d+) °C$", log, re.M))      # → ['71', '74']
```

## Un log completo, dall'inizio alla fine

Il caso tipico: un file di log del banco con righe di misura, avvisi ed errori mescolati. Si scorrono le righe, ogni regex riconosce un tipo di riga, il resto si ignora.

```python
import re

LOG = """2026-03-14 08:01:10 INFO avvio, operatore=Rossi
2026-03-14 08:05:42 MIS provino=P01 Fmax=48.2kN A=78.5mm2
2026-03-14 08:12:03 MIS provino=P02 Fmax=47,9kN A=78.6mm2
2026-03-14 08:15:30 ERR provino=P03 estensimetro scollegato
2026-03-14 08:20:11 MIS provino=P04 Fmax=49.0kN A=78.4mm2
"""

MIS = re.compile(r"MIS provino=(?P<p>\w+) Fmax=(?P<F>[\d.,]+)kN A=(?P<A>[\d.,]+)mm2")
ERR = re.compile(r"ERR provino=(?P<p>\w+) (?P<msg>.+)")
num = lambda s: float(s.replace(",", "."))

misure, errori = [], []
for riga in LOG.splitlines():
    if m := MIS.search(riga):
        F, A = num(m["F"]) * 1e3, num(m["A"])
        misure.append((m["p"], round(F / A, 1)))       # Rm in MPa
    elif m := ERR.search(riga):
        errori.append(f'{m["p"]}: {m["msg"]}')

print(misure)       # → [('P01', 614.0), ('P02', 609.4), ('P04', 625.0)]
print(errori)       # → ['P03: estensimetro scollegato']
```

Due comodità nuove:

- `m["F"]` è una scorciatoia per `m.group("F")`;
- `if m := MIS.search(riga):` assegna e controlla nella stessa riga (l'operatore `:=`, detto *walrus*): se la regex non trova niente, `m` è `None` e si passa all'`elif`.

> [!trappola] Le regex sono lo strumento giusto per il testo **libero**. Per i formati strutturati ci sono strumenti migliori: `csv` o pandas per i CSV, `json` per il JSON, una libreria apposita per XML e HTML. Una regex che «legge» un CSV si rompe alla prima virgola dentro un campo.

> [!ing] Un log ben scritto si analizza da solo. Quando sei tu a scrivere il firmware o lo script del banco, usa righe con `chiave=valore` sempre nello stesso ordine: la regex per rileggerle è una riga.

## Riepilogo

- Scrivi le regex come `r"..."`; costruiscile un mattone alla volta e provale (anche su regex101).
- `\d \w \s . [ ] * + ? {n,m} ^ $ |`; le parentesi catturano, `(?:...)` raggruppa senza catturare.
- `search` trova la prima, `findall` tutte, `fullmatch` valida un testo intero; controlla sempre il `None`.
- Gruppi con nome `(?P<nome>...)` e `groupdict()`; i gruppi sono testo da convertire.
- `re.sub` sostituisce (anche con una funzione); `re.I` e `re.M` per maiuscole e righe.
- Per CSV, JSON e XML usa i loro strumenti, non le regex.
