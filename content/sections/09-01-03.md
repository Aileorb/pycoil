Ogni misura ha un istante, ogni strumento una scadenza di taratura, ogni prova una durata. `datetime` trasforma le date scritte come testo in oggetti con cui puoi **fare i conti**.

```python
from datetime import datetime

inizio = datetime.strptime("14/03/2026 08:30", "%d/%m/%Y %H:%M")
fine = datetime.strptime("14/03/2026 17:05", "%d/%m/%Y %H:%M")
durata = fine - inizio
print(durata)                                        # → 8:35:00
print(round(durata.total_seconds() / 3600, 2), "h")  # → 8.58 h
```

`strptime` («string parse time») legge il testo secondo un **formato**: `%d` giorno, `%m` mese, `%Y` anno a quattro cifre, `%H` ore, `%M` minuti. La differenza tra due date è una **durata** (`timedelta`).

## Tre tipi: date, datetime, timedelta

- `date`: un giorno (anno, mese, giorno);
- `datetime`: un giorno con l'ora;
- `timedelta`: una durata, che si somma e si sottrae alle date.

```python
from datetime import date, datetime, timedelta

taratura = date(2026, 1, 20)
prossima = taratura + timedelta(days=180)
print(prossima)                                    # → 2026-07-19
print(prossima.year, prossima.month, prossima.day) # → 2026 7 19
print((date(2026, 3, 14) - taratura).days)         # → 53
print(date(2026, 3, 14) > taratura)                # → True

t = datetime(2026, 3, 14, 10, 22, 5)
print(t + timedelta(minutes=90))                   # → 2026-03-14 11:52:05
print(t.date(), t.hour)                            # → 2026-03-14 10
```

Le date si confrontano con `<` e `>` come i numeri, e si ordinano con `sorted`. `timedelta` accetta `days`, `hours`, `minutes`, `seconds`, `weeks`; non accetta i mesi, perché non hanno tutti la stessa lunghezza.

## Dal testo alla data e ritorno

`strptime` legge, `strftime` («string format time») scrive. I codici sono gli stessi nei due versi.

| Codice | Significato | Esempio |
|---|---|---|
| `%Y` | anno, 4 cifre | `2026` |
| `%m` | mese, 2 cifre | `03` |
| `%d` | giorno, 2 cifre | `14` |
| `%H` `%M` `%S` | ore, minuti, secondi | `08` `05` `42` |
| `%j` | giorno dell'anno | `073` |
| `%f` | microsecondi | `250000` |

```python
from datetime import datetime

t = datetime.strptime("2026-03-14 08:05:42.25", "%Y-%m-%d %H:%M:%S.%f")
print(t.strftime("%d/%m/%Y alle %H:%M"))        # → 14/03/2026 alle 08:05
print(t.strftime("%Y%m%d_%H%M%S"))              # → 20260314_080542
print(t.isoformat())                            # → 2026-03-14T08:05:42.250000
print(datetime.fromisoformat("2026-03-14T08:05:42"))   # → 2026-03-14 08:05:42
```

Se il testo non rispetta il formato, `strptime` solleva `ValueError`: con dati scritti a mano conviene un `try`/`except` che segnala la riga sbagliata.

### Perché il formato ISO nei nomi dei file

Il formato **ISO 8601** (`AAAA-MM-GG`) va dal più grande al più piccolo: per questo l'ordine alfabetico dei nomi coincide con quello cronologico. Con il formato italiano no.

```python
nomi_it = ["03-02-2026.csv", "15-01-2026.csv", "28-01-2026.csv"]
nomi_iso = ["2026-02-03.csv", "2026-01-15.csv", "2026-01-28.csv"]
print(sorted(nomi_it))      # → ['03-02-2026.csv', '15-01-2026.csv', '28-01-2026.csv']
print(sorted(nomi_iso))     # → ['2026-01-15.csv', '2026-01-28.csv', '2026-02-03.csv']
```

Il 3 febbraio finisce prima del 15 gennaio nel primo elenco: con l'ISO l'ordine è giusto senza fare niente.

## Scadenze: quali strumenti vanno tarati

Un caso quotidiano in laboratorio: un elenco di strumenti con la data dell'ultima taratura e l'intervallo previsto. Quali sono scaduti, e quali scadono nei prossimi 30 giorni?

```python
from datetime import date, timedelta

strumenti = [
    ("Calibro 0-150", date(2025, 9, 10), 365),
    ("Cella di carico 50 kN", date(2025, 4, 2), 365),
    ("Termocoppia T3", date(2026, 1, 15), 90),
    ("Durometro HRC", date(2025, 3, 28), 365),
]
oggi = date(2026, 3, 14)          # nei tuoi script: date.today()

for nome, ultima, giorni in sorted(strumenti, key=lambda s: s[1] + timedelta(days=s[2])):
    scadenza = ultima + timedelta(days=giorni)
    mancano = (scadenza - oggi).days
    stato = "SCADUTO" if mancano < 0 else "entro 30 gg" if mancano <= 30 else "ok"
    print(f"{nome:<22} {scadenza:%d/%m/%Y}  {stato}")
```

Uscita:

```text
Durometro HRC          28/03/2026  entro 30 gg
Cella di carico 50 kN  02/04/2026  entro 30 gg
Termocoppia T3         15/04/2026  ok
Calibro 0-150          10/09/2026  ok
```

Nota `{scadenza:%d/%m/%Y}`: dentro una f-string le date accettano direttamente i codici di `strftime`. E nota `oggi` scritto a mano: per provare una funzione con le date si fissa il giorno, altrimenti il risultato cambia ogni giorno e il test non è ripetibile.

## Fusi orari, in breve

Una `datetime` senza fuso orario si dice *naive*: va bene finché tutto succede nello stesso posto. Quando i dati arrivano da strumenti o server in luoghi diversi (o a cavallo del cambio dell'ora legale) servono date *aware*, con il fuso.

```python
from datetime import datetime, timedelta, timezone

utc = datetime(2026, 3, 14, 9, 0, tzinfo=timezone.utc)
roma = utc.astimezone(timezone(timedelta(hours=1)))      # ora solare italiana
print(roma.isoformat())                                  # → 2026-03-14T10:00:00+01:00
```

Sul computer, per i fusi con l'ora legale, si usa `zoneinfo`:

```python norun
from zoneinfo import ZoneInfo
t = datetime(2026, 7, 14, 9, 0, tzinfo=timezone.utc).astimezone(ZoneInfo("Europe/Rome"))
print(t)    # 2026-07-14 11:00:00+02:00  (d'estate +2)
```

> [!trappola] Salva i dati in UTC (o con il fuso esplicito) e converti all'ora locale solo quando li mostri. Due misure alle «02:30» del giorno del cambio d'ora sono ambigue se il fuso non c'è.

## File di configurazione: i parametri fuori dal codice

Un programma usato più volte non dovrebbe avere i parametri scritti dentro: cartelle, soglie, tolleranze cambiano da un lotto all'altro. Si mettono in un **file di configurazione**, che chiunque può modificare senza toccare il codice.

### JSON

Lo conosci dal Progetto 9: è il formato più diffuso tra programmi, ma non ammette commenti.

```python
import json
from pathlib import Path

config = {"cartella": "misure", "soglia_utilizzo": 0.9, "materiali": ["S235", "S355"]}
Path("config.json").write_text(json.dumps(config, indent=2))
letto = json.loads(Path("config.json").read_text())
print(letto["soglia_utilizzo"], letto["materiali"][1])     # → 0.9 S355
```

### TOML

È il formato pensato per le **persone**: si legge come un elenco di impostazioni, ammette commenti, distingue numeri, testi, liste e date. Lo usa anche `pyproject.toml`, il file che descrive i progetti Python (sezione 9.4.1). Python lo legge con `tomllib`.

```python
import tomllib

TESTO = '''
# Configurazione del collaudo del lotto 118
cartella = "misure/2026-03"
operatore = "Rossi"
data_inizio = 2026-03-14

[tolleranze]
D1 = [20.0, -0.05, 0.05]     # nominale, scostamento inferiore, superiore
L1 = [50.0, -0.10, 0.20]

[report]
formato = "xlsx"
evidenzia_scarti = true
'''

cfg = tomllib.loads(TESTO)
print(cfg["operatore"], cfg["data_inizio"])          # → Rossi 2026-03-14
print(cfg["tolleranze"]["D1"])                       # → [20.0, -0.05, 0.05]
print(cfg["report"]["evidenzia_scarti"])             # → True
print(type(cfg["data_inizio"]).__name__)             # → date
```

- `[tolleranze]` apre una **tabella**: diventa un dizionario annidato;
- `true`/`false` in minuscolo diventano `True`/`False`; le date senza virgolette diventano oggetti `date`;
- da un file si legge con `tomllib.load(open("config.toml", "rb"))`: il file va aperto in **binario** (`"rb"`).

`tomllib` legge soltanto; per scrivere TOML da Python serve la libreria `tomli-w`. Di solito non serve: il file lo scrivi tu una volta, il programma lo legge.

## Valori di default e controlli

Un file di configurazione scritto a mano può essere incompleto o sbagliato. Lo schema robusto ha tre livelli: i **default** nel codice, poi il **file**, poi le **opzioni da riga di comando**, ognuno che sovrascrive il precedente. L'operatore `|` unisce due dizionari, e a parità di chiave vince quello a destra.

```python
DEFAULT = {"soglia_utilizzo": 1.0, "formato": "xlsx", "cartella": "."}

def carica(dal_file, da_riga_di_comando):
    cfg = DEFAULT | dal_file | {k: v for k, v in da_riga_di_comando.items() if v is not None}
    if not 0 < cfg["soglia_utilizzo"] <= 1.5:
        raise ValueError(f"soglia_utilizzo fuori intervallo: {cfg['soglia_utilizzo']}")
    if cfg["formato"] not in ("xlsx", "docx", "pdf"):
        raise ValueError(f"formato sconosciuto: {cfg['formato']}")
    return cfg

print(carica({"cartella": "misure"}, {"soglia_utilizzo": None}))
print(carica({"soglia_utilizzo": 0.9}, {"soglia_utilizzo": 0.8})["soglia_utilizzo"])   # → 0.8
```

Le opzioni non specificate da riga di comando arrivano da argparse come `None`: la comprehension le scarta, così non cancellano i valori del file. Gli errori di configurazione si segnalano **subito**, all'avvio, con un messaggio che dice quale chiave è sbagliata: meglio che scoprirli a metà di un'elaborazione di due ore.

## Riepilogo

- `date`, `datetime`, `timedelta`: le date si sommano, si sottraggono, si confrontano.
- `strptime` legge il testo, `strftime` (o `f"{d:%d/%m/%Y}"`) lo scrive; nei nomi dei file usa l'ISO `AAAA-MM-GG`.
- Fissa la data «di oggi» negli esempi e nei test; salva in UTC, mostra in ora locale.
- Parametri in un file: JSON tra programmi, TOML per le persone (`tomllib`, file aperto in `"rb"`).
- Default nel codice, poi il file, poi la riga di comando (`DEFAULT | file | cli`); controlla i valori all'avvio.
