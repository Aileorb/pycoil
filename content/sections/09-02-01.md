La relazione di prova, il verbale di collaudo, la scheda tecnica: documenti con la stessa struttura e numeri diversi ogni volta. **python-docx** scrive file Word `.docx` da Python, così il documento esce già compilato, con le tabelle e i grafici al loro posto.

```python
from docx import Document

doc = Document()
doc.add_heading("Relazione di prova n. 17", level=1)
doc.add_paragraph("Provino in S355JR, prova di trazione a temperatura ambiente.")
t = doc.add_table(rows=1, cols=2)
t.rows[0].cells[0].text = "Rm"
t.rows[0].cells[1].text = "512 MPa"
doc.save("relazione_17.docx")
print(len(doc.paragraphs), len(doc.tables))     # → 2 1
```

Il documento si costruisce dall'alto in basso, come lo scriveresti: titolo, paragrafi, tabelle. Alla fine `save` scrive il file, che apri con Word o LibreOffice.

## Come è fatto un documento Word

python-docx rispecchia la struttura interna di Word:

- un **Document** contiene **paragrafi** e **tabelle**, in ordine;
- ogni paragrafo ha uno **stile** (`Normal`, `Heading 1`, `List Bullet`…) e un allineamento;
- dentro un paragrafo il testo è diviso in **run**: pezzi consecutivi con la stessa formattazione. «La tensione vale **512 MPa**» è un paragrafo con due run, il secondo in grassetto;
- una tabella ha **righe** e **celle**; ogni cella contiene a sua volta dei paragrafi;
- le **sezioni** del documento definiscono pagina, margini e orientamento.

Nell'app la libreria si installa da sola al primo uso; sul computer: `pip install python-docx` (il nome per l'`import` è `docx`).

## Testo formattato

```python
from docx import Document
from docx.enum.text import WD_ALIGN_PARAGRAPH
from docx.shared import Pt, RGBColor

doc = Document()
doc.add_heading("Esito della verifica", level=2)

p = doc.add_paragraph("La tensione massima vale ")
r = p.add_run("312,4 MPa")
r.bold = True
p.add_run(", pari al ")
r2 = p.add_run("92 %")
r2.bold = True
r2.font.color.rgb = RGBColor(0xC0, 0x39, 0x2B)      # rosso: vicino al limite
p.add_run(" della resistenza di progetto.")

for voce in ["Materiale: S355JR", "Sezione: IPE 200", "Combinazione: SLU 1"]:
    doc.add_paragraph(voce, style="List Bullet")

nota = doc.add_paragraph("Valori calcolati con γM0 = 1,05.")
nota.alignment = WD_ALIGN_PARAGRAPH.RIGHT
nota.runs[0].font.size = Pt(9)
nota.runs[0].italic = True

print([run.text for run in p.runs])
print(sum(1 for q in doc.paragraphs if q.style.name == "List Bullet"))   # → 3
doc.save("esito.docx")
```

- `add_paragraph(testo)` crea il paragrafo con un primo run; `add_run` aggiunge altri pezzi;
- `bold`, `italic`, `underline` e `font.size`, `font.color.rgb` si impostano sul **run**;
- `alignment` e `style` si impostano sul **paragrafo**;
- `Pt` (punti tipografici) e `Cm` sono le unità di misura di python-docx.

## Tabelle dai dati

Una tabella si crea con la riga di intestazione e si allunga con `add_row()`. Conviene una funzione che riceve intestazioni e righe e restituisce la tabella pronta: la riuserai in ogni report.

```python
from docx import Document

def tabella(doc, intestazioni, righe, formati=None):
    """Tabella con intestazione in grassetto; `formati` è una lista di specifiche per le colonne numeriche."""
    t = doc.add_table(rows=1, cols=len(intestazioni))
    t.style = "Table Grid"                                  # bordi su tutte le celle
    for cella, testo in zip(t.rows[0].cells, intestazioni):
        cella.text = testo
        cella.paragraphs[0].runs[0].bold = True
    for riga in righe:
        celle = t.add_row().cells
        for i, valore in enumerate(riga):
            fmt = formati[i] if formati else ""
            celle[i].text = format(valore, fmt) if fmt else str(valore)
    return t

doc = Document()
dati = [("P01", 48.2, 614.0), ("P02", 47.9, 609.4), ("P04", 49.0, 625.0)]
t = tabella(doc, ["Provino", "Fmax [kN]", "Rm [MPa]"], dati, formati=["", ".1f", ".0f"])
print(len(t.rows), len(t.columns))                          # → 4 3
print([c.text for c in t.rows[2].cells])                    # → ['P02', '47.9', '609']
doc.save("tabella.docx")
```

`format(valore, ".1f")` è la stessa specifica delle f-string (appendice D), applicata a una variabile. Per la virgola decimale all'italiana aggiungi `.replace(".", ",")`.

### Evidenziare una cella

Il colore di sfondo di una cella non ha un comando diretto in python-docx: si aggiunge un pezzetto dell'XML di Word. È una ricetta da copiare così com'è.

```python
from docx import Document
from docx.oxml import OxmlElement
from docx.oxml.ns import qn

def sfondo(cella, colore_hex):
    """Colora lo sfondo di una cella, es. sfondo(c, "FFC7CE") per il rosso chiaro degli scarti."""
    shd = OxmlElement("w:shd")
    shd.set(qn("w:val"), "clear")
    shd.set(qn("w:fill"), colore_hex)
    cella._tc.get_or_add_tcPr().append(shd)

doc = Document()
t = doc.add_table(rows=2, cols=2)
t.cell(1, 0).text, t.cell(1, 1).text = "P03", "scartato"
for c in t.rows[1].cells:
    sfondo(c, "FFC7CE")
print(t.cell(1, 1).text)              # → scartato
doc.save("scarti.docx")
```

## Grafici nel documento

Un grafico Matplotlib si salva in memoria in formato PNG (con `io.BytesIO`, un «file» che vive nella RAM) e si inserisce con `add_picture`, indicando la larghezza.

```python
import io
import matplotlib.pyplot as plt
import numpy as np
from docx import Document
from docx.shared import Cm

eps = np.linspace(0, 0.2, 200)
sigma = np.where(eps < 0.0017, 210_000 * eps, 355 + 600 * np.clip(eps - 0.0017, 0, None) ** 0.5)

fig, ax = plt.subplots(figsize=(6, 3.5))
ax.plot(eps * 100, sigma)
ax.set(xlabel="deformazione [%]", ylabel="σ [MPa]", title="Curva di trazione P01")
buf = io.BytesIO()
fig.savefig(buf, format="png", dpi=200, bbox_inches="tight")
plt.close(fig)
buf.seek(0)                                   # torna all'inizio del «file» prima di leggerlo

doc = Document()
doc.add_heading("Curva sforzo-deformazione", level=2)
doc.add_picture(buf, width=Cm(15))
doc.add_paragraph("Figura 1 – Curva di trazione del provino P01.", style="Caption")
doc.save("con_grafico.docx")
print(len(doc.inline_shapes))                 # → 1
```

- `dpi=200` rende il grafico nitido anche stampato; `bbox_inches="tight"` taglia i margini bianchi;
- `buf.seek(0)` riporta la «testina» all'inizio: dopo `savefig` è alla fine, e senza questo passaggio `add_picture` leggerebbe un file vuoto;
- `plt.close(fig)` libera la memoria: in un ciclo che crea cento report è indispensabile.

## Partire dal modello aziendale

Le aziende hanno un modello con logo, intestazione, stili e piè di pagina. Non si ricrea: si **apre** il modello e lo si completa. Con `Document("modello.docx")` ottieni un documento che ha già tutto, e puoi aggiungere paragrafi in fondo o sostituire dei segnaposto come `{{CLIENTE}}`.

```python
from docx import Document

# qui creiamo un «modello» al volo; in ufficio sarà il file .docx dell'azienda
m = Document()
m.add_paragraph("Cliente: {{CLIENTE}}")
m.add_paragraph("Commessa {{COMMESSA}} – collaudo del {{DATA}}")
m.save("modello.docx")

def compila(file_modello, valori, file_out):
    doc = Document(file_modello)
    for p in doc.paragraphs:
        for run in p.runs:
            for chiave, valore in valori.items():
                run.text = run.text.replace("{{" + chiave + "}}", str(valore))
    doc.save(file_out)
    return doc

doc = compila("modello.docx", {"CLIENTE": "Officine Meccaniche Srl", "COMMESSA": "C-2026-118", "DATA": "14/03/2026"}, "verbale.docx")
for p in doc.paragraphs:
    print(p.text)
```

Uscita:

```text
Cliente: Officine Meccaniche Srl
Commessa C-2026-118 – collaudo del 14/03/2026
```

La sostituzione lavora **run per run** per non perdere la formattazione. Il limite: se in Word modifichi a metà un segnaposto, Word può spezzarlo in più run (`{{CLI` e `ENTE}}`) e la sostituzione non lo trova più. Rimedio pratico: nel modello scrivi ogni segnaposto tutto d'un fiato, oppure ricopialo da un editor di testo.

## Rileggere un documento

python-docx legge anche: utile per estrarre una tabella di specifiche dal documento di un cliente.

```python
from docx import Document

d = Document()
t = d.add_table(rows=3, cols=2)
for i, (q, v) in enumerate([("Quota", "Valore"), ("D1", "20 ±0,05"), ("L1", "50 +0,2/-0,1")]):
    t.cell(i, 0).text, t.cell(i, 1).text = q, v
d.save("specifiche_cliente.docx")

doc = Document("specifiche_cliente.docx")
righe = [[c.text for c in r.cells] for r in doc.tables[0].rows]
print(righe[1:])            # → [['D1', '20 ±0,05'], ['L1', '50 +0,2/-0,1']]
```

## Pagina e margini

```python
from docx import Document
from docx.enum.section import WD_ORIENT
from docx.shared import Cm

doc = Document()
s = doc.sections[0]
s.orientation = WD_ORIENT.LANDSCAPE
s.page_width, s.page_height = s.page_height, s.page_width     # in orizzontale vanno scambiate
s.left_margin = s.right_margin = Cm(2)
print(round(s.page_width.cm, 1), round(s.page_height.cm, 1))   # → 27.9 21.6
```

Il modello vuoto di python-docx usa il formato Letter americano (21,6 × 27,9 cm): per l'A4 imposta `s.page_width = Cm(21)` e `s.page_height = Cm(29.7)`, oppure parti da un modello aziendale, che è già A4.

> [!trappola] python-docx non calcola i campi di Word: indice, numeri di pagina e riferimenti incrociati si aggiornano solo aprendo il file in Word (F9). E non converte in PDF: per quello si lancia LibreOffice da Python, `soffice --headless --convert-to pdf relazione.docx` (sezione 9.3.1), oppure si scrive il PDF direttamente (sezione successiva).

> [!ing] Un report generato non è un report verificato. Prima di consegnarlo aprilo, controlla una pagina a campione contro i dati grezzi e metti nel documento la versione dello script e la data di generazione: chi lo legge fra un anno deve poter ricostruire come è stato fatto.

## Riepilogo

- Document → paragrafi (con stile) → run (con formattazione); tabelle → righe → celle.
- `add_heading`, `add_paragraph`, `add_run` (bold, italic, `font.size = Pt(...)`), `style="List Bullet"`.
- Tabelle con una funzione riusabile: intestazione in grassetto, `add_row`, `format(valore, ".1f")`.
- Grafici: `savefig` in un `BytesIO`, `seek(0)`, `add_picture(buf, width=Cm(15))`, poi `plt.close`.
- Parti dal modello aziendale con `Document("modello.docx")` e sostituisci i segnaposto run per run.
- Indici, campi e conversione in PDF stanno fuori da python-docx.
