Molti strumenti dell'ingegnere sono programmi a sé: un meshatore (Gmsh), un solutore FEM (CalculiX), LibreOffice per convertire i documenti. Python li **lancia**, aspetta che finiscano, legge cosa hanno scritto e passa al passo successivo: così una catena di dieci programmi diventa un solo comando.

```python norun
import subprocess
import sys

r = subprocess.run([sys.executable, "--version"], capture_output=True, text=True)
print(r.returncode)          # 0 = tutto bene
print(r.stdout.strip())      # Python 3.13.1
```

`subprocess.run` riceve il comando come **lista**: il programma e poi ogni argomento separato. `sys.executable` è il percorso del Python che sta girando: lo usiamo negli esempi perché c'è sicuramente su ogni computer.

<!-- /card -->

> [!nota] Il browser non può lanciare programmi: gli esempi che chiamano `subprocess.run` sono da provare sul computer (hanno il bollino *Desktop*). Le parti che preparano i comandi e leggono i risultati, invece, girano anche qui.

## run, passo per passo

```python norun
import subprocess

r = subprocess.run(
    ["ccx", "-i", "trave"],      # il programma e i suoi argomenti, uno per elemento
    cwd="casi/trave_01",         # cartella in cui farlo girare
    capture_output=True,         # raccogli quello che scrive invece di mostrarlo
    text=True,                   # restituisci testo (str), non byte
    timeout=600,                 # dopo 10 minuti interrompi
)
print(r.returncode)              # codice di uscita: 0 se è andato tutto bene
print(r.stdout[-500:])           # le ultime righe dell'output normale
print(r.stderr)                  # i messaggi di errore
```

Il risultato è un oggetto `CompletedProcess` con quattro attributi: `args` (il comando lanciato), `returncode`, `stdout` e `stderr`. I programmi scrivono su due canali separati: **stdout** per i risultati e **stderr** per errori e avvisi.

| Argomento | A cosa serve |
|---|---|
| `capture_output=True` | raccoglie stdout e stderr nel risultato |
| `text=True` | converte l'output in stringhe |
| `cwd="cartella"` | fa girare il programma in quella cartella (molti solutori scrivono i risultati lì) |
| `timeout=secondi` | interrompe un programma bloccato |
| `check=True` | solleva un'eccezione se il codice di uscita non è 0 |
| `input="testo"` | manda del testo al programma, come se lo scrivessi da tastiera |

## Perché una lista e non una stringa

Il comando si può scrivere come stringa unica con `shell=True`, ma è una cattiva abitudine: con nomi di file che contengono spazi si rompe, e se una parte del comando arriva da un utente o da un file, chi la scrive può far eseguire al computer qualunque altra cosa. Con la **lista** ogni elemento arriva al programma intatto, spazi compresi.

Il modulo `shlex` converte tra le due forme, ed è comodo per stampare il comando nei log o per copiare un comando dal manuale di un programma:

```python
import shlex

cmd = ["gmsh", "piastra forata.geo", "-2", "-o", "piastra.msh"]
print(shlex.join(cmd))          # → gmsh 'piastra forata.geo' -2 -o piastra.msh
print(shlex.split("ccx -i 'trave lunga'"))   # → ['ccx', '-i', 'trave lunga']
```

## Quando qualcosa va storto

Tre cose possono andare male, ognuna con la sua eccezione:

- il programma **non esiste** (non installato o non nel PATH): `FileNotFoundError`;
- il programma gira ma **fallisce**: codice di uscita diverso da 0, che con `check=True` diventa `subprocess.CalledProcessError`;
- il programma **non finisce**: `subprocess.TimeoutExpired`.

Una funzione che gestisce tutti e tre i casi, da tenere nei propri script:

```python norun
import shlex
import subprocess

def esegui(cmd, cartella=".", timeout=3600):
    """Lancia un programma esterno; restituisce lo stdout o solleva RuntimeError con un messaggio chiaro."""
    try:
        r = subprocess.run(cmd, cwd=cartella, capture_output=True, text=True, timeout=timeout, check=True)
    except FileNotFoundError:
        raise RuntimeError(f"programma non trovato: {cmd[0]} (è installato? è nel PATH?)") from None
    except subprocess.CalledProcessError as e:
        raise RuntimeError(f"{shlex.join(cmd)} è uscito con codice {e.returncode}:\n{e.stderr[-2000:]}") from None
    except subprocess.TimeoutExpired:
        raise RuntimeError(f"{shlex.join(cmd)} non ha finito entro {timeout} s") from None
    return r.stdout
```

`raise ... from None` sostituisce l'eccezione originale con la tua, più leggibile, senza stampare due traceback uno dentro l'altro. Le ultime righe di `stderr` sono quasi sempre quelle che spiegano il problema.

Per controllare **prima** che un programma sia installato c'è `shutil.which`, che restituisce il percorso completo o `None`:

```python norun
import shutil

if shutil.which("ccx") is None:
    raise SystemExit("CalculiX non è installato: https://www.calculix.de/")
```

## Preparare i file di input da un modello

I solutori leggono file di testo. Per uno studio parametrico (dieci spessori, cinque carichi) si scrive **un** modello con dei segnaposto e si genera un file per ogni caso. `string.Template` usa segnaposto con il dollaro (`$spessore`), che non si confondono con le graffe che molti formati usano già.

```python
from pathlib import Path
from string import Template

MODELLO = Template("""*HEADING
Piastra spessore $s mm, carico $F N
*MATERIAL, NAME=ACCIAIO
*ELASTIC
210000, 0.3
*SHELL SECTION, ELSET=EALL, MATERIAL=ACCIAIO
$s
*CLOAD
NCARICO, 2, $F
""")

casi = []
for s in [4, 6, 8]:
    for F in [1000, 2000]:
        nome = f"piastra_s{s}_F{F}"
        cartella = Path("casi") / nome
        cartella.mkdir(parents=True, exist_ok=True)
        (cartella / f"{nome}.inp").write_text(MODELLO.substitute(s=s, F=F))
        casi.append(cartella)

print(len(casi), "casi")                                   # → 6 casi
print(casi[3].name)                                        # → piastra_s6_F2000
print((casi[3] / "piastra_s6_F2000.inp").read_text().splitlines()[1])   # → Piastra spessore 6 mm, carico 2000 N
```

`substitute` solleva `KeyError` se manca un valore: meglio così che un file con `$s` rimasto dentro, che il solutore rifiuterebbe con un messaggio oscuro.

## Leggere i risultati

Dopo il calcolo si leggono i numeri dal file di output o da stdout, di solito con le regex della sezione 9.1.2. Qui un output in stile Gmsh e un file di risultati semplificato:

```python
import re

out_gmsh = """Info    : Meshing 2D...
Info    : Done meshing 2D (Wall 0.124s, CPU 0.118s)
Info    : 1842 nodes 3790 elements
Info    : Writing 'piastra.msh'..."""

m = re.search(r"(\d+) nodes (\d+) elements", out_gmsh)
nodi, elementi = int(m[1]), int(m[2])
print(nodi, elementi)                 # → 1842 3790

risultati = """ displacements (vx,vy,vz) for set NALL and time  0.1000000E+01
        17  1.203E-03 -4.512E-02  0.000E+00
        18  1.198E-03 -4.874E-02  0.000E+00
        19  1.101E-03 -4.630E-02  0.000E+00"""
vy = [float(r.split()[2]) for r in risultati.splitlines()[1:]]
print(f"freccia massima {max(map(abs, vy)):.4f} mm")   # → freccia massima 0.0487 mm
```

`float` legge da solo la notazione scientifica `-4.874E-02`.

## Una catena completa

Mesh, calcolo, lettura dei risultati, per ogni caso: se un caso fallisce, si annota e si passa al successivo invece di perdere tutta la notte di calcoli.

```python norun
import csv
from pathlib import Path

esiti = []
for cartella in sorted(Path("casi").iterdir()):
    nome = cartella.name
    try:
        esegui(["gmsh", f"{nome}.geo", "-2", "-o", f"{nome}.msh"], cartella, timeout=300)
        esegui(["ccx", "-i", nome], cartella, timeout=3600)
        freccia = leggi_freccia(cartella / f"{nome}.dat")       # funzione tua, con le regex
        esiti.append({"caso": nome, "freccia_mm": freccia, "errore": ""})
    except RuntimeError as e:
        esiti.append({"caso": nome, "freccia_mm": None, "errore": str(e).splitlines()[0]})

with open("riepilogo.csv", "w", newline="") as f:
    w = csv.DictWriter(f, fieldnames=["caso", "freccia_mm", "errore"], delimiter=";")
    w.writeheader()
    w.writerows(esiti)
```

```bash

```

```python norun
import subprocess

```

Per i programmi che girano a lungo e di cui vuoi vedere l'avanzamento riga per riga mentre lavorano, invece di `run` si usa `subprocess.Popen`:

```python norun
import subprocess

with subprocess.Popen(["ccx", "-i", "trave"], stdout=subprocess.PIPE, text=True) as p:
    for riga in p.stdout:                    # arriva una riga alla volta, mentre il solutore lavora
        if "increment" in riga:
            print(riga.strip())
print("codice di uscita:", p.returncode)
```

> [!trappola] Su Windows molti programmi non sono nel PATH: scrivi il percorso completo con `Path(r"C:\Program Files\...\programma.exe")`, con la `r` davanti per non far interpretare le barre rovesciate. E metti percorso e versione del programma nel file di configurazione, non nel codice.

> [!ing] Uno studio parametrico automatico vale quanto il controllo dei suoi risultati: lancia per primo un caso di cui conosci la soluzione (una trave appoggiata, una lastra con foro di Kirsch) e confronta. Se quel caso torna, gli altri cento hanno senso.

## Riepilogo

- `subprocess.run([programma, arg1, arg2], capture_output=True, text=True)`: comando come lista, mai `shell=True`.
- Il risultato ha `returncode` (0 = ok), `stdout`, `stderr`; `cwd`, `timeout` e `check=True` per lavorare in sicurezza.
- Gestisci `FileNotFoundError`, `CalledProcessError`, `TimeoutExpired`; `shutil.which` controlla l'installazione.
- File di input da un modello con `string.Template`; risultati letti con regex e `float`.
- In una catena di casi, annota i fallimenti e continua; prima di tutto, un caso con soluzione nota.
