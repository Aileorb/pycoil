Sempre più macchine e servizi parlano attraverso una **API web**: il gestionale della produzione, la stazione meteo del cantiere, il sensore IoT sul compressore, il portale del fornitore. Python fa una richiesta a un indirizzo, riceve una risposta in **JSON** e la trasforma in dizionari e liste.

```python
import json

risposta = '{"stazione": "Torino", "misure": [{"ora": "08:00", "T": 4.2}, {"ora": "09:00", "T": 6.1}]}'
dati = json.loads(risposta)
print(dati["stazione"], [m["T"] for m in dati["misure"]])   # → Torino [4.2, 6.1]
```

`json.loads` («load string») converte il testo JSON nelle strutture di Python che conosci: gli oggetti `{...}` diventano dizionari, gli array `[...]` liste.

## Che cos'è un'API web

Un'API web è un programma che gira su un server e risponde a **richieste HTTP**, le stesse che fa il browser quando apri una pagina. Invece di una pagina da leggere, restituisce dati da elaborare.

- L'**indirizzo** (URL) indica la risorsa: `https://api.esempio.it/v1/macchine/42/misure`;
- i **parametri** dopo il `?` la filtrano: `?dal=2026-03-01&grandezza=temperatura`;
- il **metodo** dice cosa vuoi fare: `GET` leggere, `POST` creare, `PUT`/`PATCH` modificare, `DELETE` cancellare;
- le **intestazioni** (*headers*) portano informazioni di servizio, come la chiave di accesso;
- la risposta ha un **codice di stato** e un **corpo**, di solito in JSON.

| Codice | Significato | Cosa fare |
|---|---|---|
| 200 | OK | leggi i dati |
| 201 | creato | il `POST` è andato a buon fine |
| 400 | richiesta sbagliata | controlla parametri e formato |
| 401 / 403 | non autorizzato / vietato | controlla la chiave di accesso |
| 404 | non trovato | indirizzo o risorsa sbagliati |
| 429 | troppe richieste | aspetta e riprova più lentamente |
| 500 / 503 | errore del server / non disponibile | riprova più tardi |

I codici 4xx sono errori **tuoi** (riprovare uguale non serve), i 5xx sono del **server** (riprovare dopo un po' spesso funziona).

## JSON in Python

| JSON | Python |
|---|---|
| oggetto `{"a": 1}` | `dict` |
| array `[1, 2]` | `list` |
| stringa `"S355"` | `str` |
| numero `12`, `12.5` | `int`, `float` |
| `true` / `false` | `True` / `False` |
| `null` | `None` |

```python
import json

testo = '{"pezzo": "A017", "conforme": false, "note": null, "quote": {"D1": 20.012, "L1": 50.1}}'
d = json.loads(testo)
print(d["conforme"], d["note"], d["quote"]["D1"])         # → False None 20.012

uscita = {"lotto": "2026-118", "scarti": ["A017", "A031"], "tasso": 0.042, "operatore": "Gonzalez Núñez"}
print(json.dumps(uscita))
print(json.dumps(uscita, ensure_ascii=False))
print(json.dumps({"ok": True, "x": None}))                # → {"ok": true, "x": null}
```

- `json.dumps` fa il contrario di `loads`: da Python a testo JSON; `indent=2` lo rende leggibile a capo;
- di default le lettere accentate diventano codici come `ú`: con `ensure_ascii=False` restano leggibili;
- `json.load(f)` e `json.dump(obj, f)`, senza la `s`, lavorano direttamente sui file aperti.

Non tutto è convertibile: date, `set` e numeri NumPy danno `TypeError`. Il parametro `default` indica cosa fare con gli oggetti sconosciuti.

```python
import json
from datetime import date

misura = {"data": date(2026, 3, 14), "valori": {12.5, 12.7}}
try:
    json.dumps(misura)
except TypeError as e:
    print(e)                                    # → Object of type date is not JSON serializable

def converti(o):
    if isinstance(o, date):
        return o.isoformat()
    if isinstance(o, set):
        return sorted(o)
    raise TypeError(f"non so convertire {type(o).__name__}")

print(json.dumps(misura, default=converti))     # → {"data": "2026-03-14", "valori": [12.5, 12.7]}
```

## Navigare nelle risposte annidate

Le risposte vere sono spesso profonde, con dizionari dentro liste dentro dizionari. Si scende un livello alla volta, e `get` evita gli errori quando un campo è facoltativo.

```python
import json

risposta = json.loads('''{
  "macchina": {"id": 42, "nome": "Tornio CNC 3"},
  "letture": [
    {"t": "2026-03-14T08:00:00", "grandezze": {"T_mandrino": 41.2, "vibrazione": 1.8}},
    {"t": "2026-03-14T08:10:00", "grandezze": {"T_mandrino": 43.9}},
    {"t": "2026-03-14T08:20:00", "grandezze": {"T_mandrino": 47.5, "vibrazione": 3.4}}
  ]
}''')

print(risposta["macchina"]["nome"])                                     # → Tornio CNC 3
T = [l["grandezze"]["T_mandrino"] for l in risposta["letture"]]
vib = [l["grandezze"].get("vibrazione") for l in risposta["letture"]]
print(T, vib)                                                           # → [41.2, 43.9, 47.5] [1.8, None, 3.4]
allarmi = [l["t"][11:16] for l in risposta["letture"] if l["grandezze"].get("vibrazione", 0) > 3]
print(allarmi)                                                          # → ['08:20']
```

Per lavorarci con pandas, `pd.json_normalize` «appiattisce» le strutture annidate in colonne:

```python
import pandas as pd

letture = [
    {"t": "08:00", "grandezze": {"T_mandrino": 41.2, "vibrazione": 1.8}},
    {"t": "08:10", "grandezze": {"T_mandrino": 43.9}},
]
df = pd.json_normalize(letture)
print(list(df.columns))      # → ['t', 'grandezze.T_mandrino', 'grandezze.vibrazione']
```

## Costruire un indirizzo con i parametri

I parametri vanno **codificati**: spazi, accenti e simboli hanno una forma speciale negli URL. `urllib.parse.urlencode` lo fa per te a partire da un dizionario.

```python
from urllib.parse import urlencode, urljoin

base = "https://api.esempio.it/v1/"
url = urljoin(base, "macchine/42/misure")
parametri = {"dal": "2026-03-01", "grandezza": "T mandrino", "limite": 500}
print(url + "?" + urlencode(parametri))
# → https://api.esempio.it/v1/macchine/42/misure?dal=2026-03-01&grandezza=T+mandrino&limite=500
```

Con la libreria `requests` (prossimo paragrafo) non serve nemmeno: le passi il dizionario e codifica lei.

## requests, passo per passo

Sul computer la libreria più usata per le richieste HTTP è **requests** (`pip install requests`). Le richieste dal browser seguono regole diverse, per questo questi esempi sono da provare sul computer.

```python norun
import requests

r = requests.get(
    "https://api.open-meteo.com/v1/forecast",
    params={"latitude": 45.07, "longitude": 7.69, "hourly": "temperature_2m", "forecast_days": 1},
    timeout=10,                         # secondi: senza, uno script può restare appeso per sempre
)
r.raise_for_status()                    # solleva un'eccezione se il codice è 4xx o 5xx
dati = r.json()                         # come json.loads(r.text)
ore = dati["hourly"]["time"]
temperature = dati["hourly"]["temperature_2m"]
print(r.status_code, ore[0], temperature[0])
```

Open-Meteo è un servizio meteo gratuito che non richiede registrazione: un buon banco di prova. Per la maggior parte delle API aziendali serve invece una **chiave**, che si manda in un'intestazione:

```python norun
import os
import requests

sessione = requests.Session()                                        # riusa la connessione per più richieste
sessione.headers["Authorization"] = f"Bearer {os.environ['API_TOKEN']}"

r = sessione.get("https://mes.azienda.it/api/v1/ordini", params={"stato": "aperto"}, timeout=10)
r.raise_for_status()
ordini = r.json()

nuova = {"macchina": 42, "grandezza": "T_mandrino", "valore": 47.5, "t": "2026-03-14T08:20:00"}
r = sessione.post("https://mes.azienda.it/api/v1/letture", json=nuova, timeout=10)   # json= converte e imposta le intestazioni
print(r.status_code)                                                                    # 201 se è stata creata
```

> [!trappola] Il **`timeout`** va messo sempre: senza, se il server non risponde, lo script aspetta all'infinito. E la chiave di accesso, come le password, si legge da una variabile d'ambiente, mai scritta nel codice.

## Riprovare con pazienza

Le reti falliscono: un server occupato, un Wi-Fi che cade per un secondo. Per gli errori temporanei (5xx, 429, connessione interrotta) si riprova, aspettando ogni volta di più (*backoff esponenziale*). La logica si può scrivere e provare senza rete, con una funzione finta che fallisce le prime volte:

```python
import time

class ErroreTemporaneo(Exception):
    pass

def con_tentativi(fn, tentativi=4, attesa=0.5, dormi=time.sleep):
    """Chiama fn(); se fallisce con un errore temporaneo riprova, raddoppiando l'attesa."""
    for i in range(tentativi):
        try:
            return fn()
        except ErroreTemporaneo:
            if i == tentativi - 1:
                raise
            dormi(attesa * 2 ** i)              # 0.5, 1, 2 secondi…

chiamate = []
def server_capriccioso():
    chiamate.append(1)
    if len(chiamate) < 3:
        raise ErroreTemporaneo("503")
    return {"ok": True}

attese = []
print(con_tentativi(server_capriccioso, dormi=attese.append))   # → {'ok': True}
print(len(chiamate), attese)                                    # → 3 [0.5, 1.0]
```

Passare la funzione `dormi` come parametro è un piccolo trucco da professionista: nel programma vero è `time.sleep`, nei test una funzione che annota le attese invece di aspettare davvero.

## Risposte a pagine

Le API non restituiscono 100 000 righe in un colpo: le dividono in **pagine**, e ogni risposta dice come chiedere la successiva. Il ciclo è sempre lo stesso: chiedi una pagina, aggiungi i dati, prosegui finché c'è una pagina seguente.

```python
def scarica_tutto(chiedi_pagina):
    """`chiedi_pagina(n)` restituisce {"dati": [...], "prossima": n+1 oppure None}."""
    tutto, pagina = [], 1
    while pagina is not None:
        risposta = chiedi_pagina(pagina)
        tutto.extend(risposta["dati"])
        pagina = risposta["prossima"]
    return tutto

FINTO = {1: {"dati": [1, 2, 3], "prossima": 2}, 2: {"dati": [4, 5, 6], "prossima": 3}, 3: {"dati": [7], "prossima": None}}
print(scarica_tutto(FINTO.get))         # → [1, 2, 3, 4, 5, 6, 7]
```

Nel programma vero `chiedi_pagina` fa la richiesta con `requests` e `params={"pagina": n}`; il resto non cambia.

> [!nota] Dentro l'app (Pyodide, nel browser) `requests` non funziona così com'è: il browser permette le richieste solo con regole sue. Esiste `pyodide.http.pyfetch`, ma per lavorare con le API vere usa il computer.

> [!ing] Prima di scrivere codice, leggi la documentazione dell'API: indirizzi, parametri, limiti di richieste, formato delle date e delle unità. Poi prova una richiesta a mano (nel browser per un `GET`, o con `curl` nel terminale) e salva una risposta vera in un file: ti servirà per provare il programma senza interrogare il server ogni volta.

## Riepilogo

- Un'API web risponde a richieste HTTP (`GET`, `POST`…) con un codice di stato e dati JSON; 4xx errori tuoi, 5xx del server.
- `json.loads`/`dumps` (e `load`/`dump` sui file); `ensure_ascii=False`, `default=` per date e set.
- Scendi nelle risposte annidate un livello alla volta, `get` per i campi facoltativi, `pd.json_normalize` per le tabelle.
- `requests.get(url, params=..., timeout=...)`, `raise_for_status()`, `r.json()`; chiavi nelle variabili d'ambiente.
- Riprova gli errori temporanei con attese crescenti; segui le pagine finché ce ne sono.
